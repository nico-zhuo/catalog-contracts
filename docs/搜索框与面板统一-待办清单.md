### 0.2 多模态输入面板（recon，含 Lead 实测证据）

**事实**：128 个工具页共用同一个 `UnifiedPromptBar`；结构（容器/工具栏顺序）**已统一**：
`工具名胶囊 | 模型选择 | 参数胶囊 | … | Generate 胶囊`。

实测（生产，桌面 1440；`/tmp/ab-team/panel-probe2.json` + `/tmp/ab-team/panel_shots2/*.png`）：

| 输入区形态 | 代表页面 | 面板高度 |
|---|---|---|
| textarea 纯文本 | album-cover / logo-maker / text-to-video / body-generator / text-to-music / pixel-avatar / er-diagram | **119** |
| textarea + 图片参考上传槽 | text-to-image / photo-retouching / image-to-3d | **143** |
| placeholder-only（无 textarea） | 3d-character / audio-to-video | **131** |
| 视频上传槽（无 textarea） | video-enhancer | **109** |

**根因**：不是布局组件不一致，而是「输入区内容」按工具能力变化（图片/音频/视频上传槽、placeholder-only、纯文本）导致**输入行高度跳变**；text-to-image 因为带参考图上传槽，看起来更“完整”。
**判定**：
1. 真正的视觉不一致 = 输入行高度/垂直对齐/占位符样式在不同工具间跳变（可修，P-A）。
2. 合理内容差异 = 工具本身不支持参考图/无文本输入 → 不应强行加空上传位（若要“完全一样”属产品决策，不在本批）。
3. 无「页面没走新面板 / 旧布局残留」问题（全 128 页均同组件；两个 `found:false` 是已下线的 301 页，预期）。
